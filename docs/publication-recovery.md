# Publication reconciliation

Uncertain Provider writes are not automatically repeated. Publication receipts bind the Task fingerprint, original/current candidate, PR, evidence, Handoff, consumed operation and retained source bytes. Read-only reconciliation inspects bounded complete comment/PR history using single-repository read permission. Missing pages, duplicate identities, malformed history, ref drift or ambiguous results stop recovery.

Human resume authorization is an actual PR comment from a policy-approved login and numeric GitHub ID, bound to the expected receipt/body fingerprint. It is not an arbitrary URL or free-text command grant. Adoption can patch only that receipt-bound existing comment; it cannot POST a second Handoff or edit unrelated history. Revision retains its bounded PR-comment token and has no push/PR/Ready/Review/merge capability.

The CLI refuses mixed/incomplete recovery options and repository/API/Git passthrough. A confirmed exact-head Handoff must be read back before a revision Event links. Event-only retry has no Provider side effects; failures preserve original diagnostics and consumed receipts for the next explicit bounded operation.
