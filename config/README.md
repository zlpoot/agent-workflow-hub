# Deployment configuration inventory (1.0)

Current supported code: main v0.2/v0.2.1-R1, Client 0.4.4. The files here are **documentation and inert examples**, never automatically loaded. Put real configurations and secrets in an operator-owned directory outside every repository. Examples use fictional paths/IDs, zero hashes and an expired viewer session; they provide no GitHub write or Operator authority. Replace Unix example paths with native absolute Windows paths (for example `C:\awh-runtime\trusted.json`) where appropriate. Provision owner-only ACLs on Windows; Unix private keys/credentials require owner-only modes.

Three separate layers:

1. Deployment parameters: listener ports, endpoint, files, state and runtime installation, loaded only from an explicitly selected external source.
2. Trusted Profile/Operator policy: separately approved immutable versions, fixed repository/branch/verification/executor/permission bindings. CP trusted configuration is policy input, not ordinary project configuration. Normal serve now requires its versions to already match SQLite; static `mvp` seeding remains a separately authorized legacy operation. No production Operator policy loader exists yet.
3. `.awh/project.yaml`: minimal project/repository/Profile-ref identity only. It cannot grant App API, selected-set or command rights. Issue/PR text and environment variables cannot expand those rights either.

CP deployment/trusted/TLS/database paths now reject missing/empty/wrong files, repository ancestors, relative/dot traversal paths and symlinks (including linked parent directories). Normal serve checks v2 tables, immutability trigger presence and exact Profile/Project bindings before writable open, and never migrates/seeds. This is not a database authenticity proof against a malicious operator-controlled replacement, nor a logical CP service UUID; #27 remains open. Keep deployment directories exclusively operator-owned during startup. Existing Store constructor legacy behavior is retained for controlled embedded initialization, history fixtures and static seed tools.

## Schema and source contract

`schemas/` is JSON Schema draft 2020-12. `cp-trusted.schema.json` references `urn:awh:protocol:1.0#/$defs/profile_policy` from `src/protocol/schema.json`; register that schema when validating offline. Schemas reject extra fields and invalid basic field types; authoritative closed runtime validators additionally check files, byte limits, endpoint rules, TLS, duplicates, hashes/identity agreement and live permissions. Schemas do not provision anything. Sources/version live in this inventory and schema `$id`; don't add unrecognized provenance fields to legacy config.
